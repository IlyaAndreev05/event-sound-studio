# Platform check (2026-10-16)

Development environment: Ubuntu 26.04.1 LTS, GNOME Shell 50.1 on Wayland, OpenJDK/JDK 25.0.4.1 runtime. PipeWire and WirePlumber 1.6.2 are active. `wpctl`, `pw-dump`, `pw-link`, `gdbus`, and `busctl` are available; `pactl` is not. `/dev/input/event*` nodes are `root:input`; the current user belongs to `input`, but this app still requires an explicit per-device opt-in. No input event values were read. Gradle was not installed; a Gradle Wrapper is checked in.

Java Sound enumeration is used to populate the output list. `EventSoundStudio --diagnose-audio` enumerates mixer capabilities without opening an output line or playing audio. It reported the default mixer as `alsa_playback.EventSoundStudio [default]`; explicit hardware entries included NVIDIA HDMI, `Generic [plughw:1,1]`, and USB `Device [plughw:3,0]`. The separate `Port Generic [hw:1]` entry did not report support for the app's 48 kHz/16-bit/stereo PCM format. Java Sound did not expose a mixer explicitly named `Family 17h` or a selectable `Generic [plughw:1,0]` analog endpoint. The default mixer was not opened, so it has not been acoustically mapped to a connector.

The user reports that the vibration transducer is currently connected to the selected `Family 17h (Models 00h-0fh)` line output. Because that output currently carries the transducer, no audible playback or output-loss test was performed. The amplifier, transducer model, and wiring have not been independently identified. Physical latency and acoustic/vibration response are not claimed. The `--diagnose-audio` command is a safe inventory only, not a playback test.
