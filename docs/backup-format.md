# Backup and restore

Use **Profiles → Backup and transfer** to export or restore a full local backup. The archive contains `config.yaml`, which holds profiles, event types, groups, bindings and sound metadata, plus every referenced normalized/original WAV file under `data/`. `manifest.json` records a SHA-256 digest for every included file. The Export ZIP button beside a profile creates a self-contained package with that profile, its enabled bindings, referenced events/groups/sounds, protected built-in groups and their default sounds, and those sounds' WAV resources. It sets profile and binding outputs to portable defaults and drops source-profile overrides and unrelated catalog records. The Sounds page can export a checked sound set with recursive `copy_of`/`fragment_of` provenance and WAV resources; the Bindings page can export checked bindings with their dependencies as an inactive-profile package.

The importer validates the manifest, checks every file digest, rejects absolute and traversing paths, caps the archive at 512 files and 512 MiB expanded size, then previews the archive contents before applying anything. A full backup replaces the current YAML only after confirmation. A selected-profile package merges that profile into the current config: the active profile, settings, API state, and source-profile overrides stay as they are, while the imported profile remains inactive. Conflicting IDs are remapped consistently across profiles, bindings, event types, combos, custom groups, sounds, and their references. Built-in groups in the destination are preserved, and only sounds used by the imported profile and its custom groups/dependencies are added. Existing audio files are retained; identical resources are reused and different files with the same path are written under `library/imported/` with their config paths updated. The config store still checks for concurrent external edits before saving.

For safety, a full backup restore forces keyboard, mouse, GNOME event sources and the local API off. A profile merge does not change the destination's input/API settings. Profile and binding output selectors in a selected-profile package are reset to portable defaults. When a full backup refers to output names absent on this computer, import offers an explicit per-name mapping to a currently available Java Sound output; leaving a row blank preserves its old selector, which the UI marks unavailable until the user changes it. The mapping uses output names because Java Sound does not provide a portable hardware identity here; confirm that the selected output is physically connected to the intended device before playing audio.

The current ZIP format is version 2. It identifies the application and the config schema version in `manifest.json`; the importer checks those fields against `config.yaml`. Version 1 archives are upgraded during preview, including early full backups that did not record an archive kind. Unknown future versions, unsupported kinds, and mismatched config-schema declarations are rejected before installation. Individual library WAVs and generated WAV output can also be saved outside the app. A valid checksum shows that an archive was not accidentally changed; it does not establish who created it.
