# Event Sound Studio

A local desktop sound library and event-to-effect player, released as version 0.2.0. Settings live in `~/.config/event-sound-studio/config.json`; first launch migrates `config.yaml` and preserves it as `config.yaml.before-json`. Event audio targets the isolated `audio_matrix_events` PipeWire sink and stays silent if that target is unavailable; previews and the generator use a separate `preview_output`. The current default document is `src/main/resources/config.example.json`; `config.example.yaml` remains a migration example. Built-in and imported WAV files remain separate assets.

## Run

Use Java 25 and `./gradlew run`. Build a local Debian package with `./gradlew packageDeb`; it appears under `build/deb/`. Keyboard and mouse monitoring are opt-in per device; the app never records key sequences. Key repeats are ignored by default or can be throttled, and common media keys have individual event IDs. Read [docs](docs/) for configuration, permissions, API, and packaging details. The optional GNOME event extension is installed with `scripts/install-gnome-events.sh` and enabled separately in GNOME Extensions; enable the GNOME source in app settings only after installing the extension. It forwards generic event names without window titles or contents. Alt+Tab key events remain distinct from GNOME focus changes; an optional setting can suppress the GNOME focus sound within 750 ms after Alt+Tab and is off by default.

Event playback is pinned to the `audio_matrix_events` virtual sink provided by Audio Matrix. Until the Audio Matrix user service is enabled, event sounds remain silent; they never fall back to the current system output. After Audio Matrix is installed, enabling that user service is an explicit system action with `/opt/audiomatrix/bin/enable-audiomatrix-events-service.sh`; undo it with `/opt/audiomatrix/bin/disable-audiomatrix-events-service.sh`. This service creates an isolated sink and does not select it as the system output.

For a read-only Java Sound output inventory, run `./gradlew run --args='--diagnose-audio'` or `EventSoundStudio --diagnose-audio` from the installed package. It lists stable output selectors and mixer capabilities without opening an output line or playing audio. On ALSA, selectors use the device's sysfs path and PCM device where available; other Java Sound mixers use their name/vendor/description metadata. A selector matching multiple mixers is not offered, and legacy mixer names resolve only when unique. Inventory cannot prove which physical connector a system-default mixer reaches.

The sound library exports an individual WAV or a selected sound-set ZIP with its provenance dependencies; the generator can write its result directly to a standalone WAV file. Selected bindings can be exported as a ZIP that imports as a new profile. The Profiles page can also export a complete profile or create a full configuration backup. Version 4 archives contain `config.json`; older YAML archives still import through migration. Import checks the versioned manifest, hashes, and paths. Profile/binding-set archives merge as inactive profiles, while a sound-set ZIP merges into the library; ID conflicts are remapped and current settings/source states are preserved. A full backup replaces the JSON config and restores with keyboard, mouse, GNOME, and API sources disabled. Only preview outputs can be remapped; event outputs remain pinned to the isolated Audio Matrix sink.

Profiles can select their own event master volume; event playback stays on the Audio Matrix virtual sink. Previews and generator playback use the separate `settings.preview_output` selector.

The Events & bindings screen manages named custom events and named sound bindings independently. One event can launch several bindings; bindings can be edited, copied, enabled per profile, and deleted with a one-step undo. Binding priority and cooldown are validated in JSON and exposed alongside per-binding audio controls.

Profiles can be assigned independently to keyboard, mouse/wheel, and system/API event sources. Each source follows the active profile unless an override is selected; per-voice output and master volume follow the chosen source profile.
